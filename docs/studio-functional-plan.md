# Studio 功能与界面重整方案

2026-10-14。依据用户对现有 Studio 不满意、希望分析功能并将 Works 归入 Studio 的反馈。本文件是产品方案，不表示下列能力已实现。

## 当前页面的主要问题

现有页面展示公开记录数量和主题分布，不能回答当前学习阶段、卡点、下一步行动。相对数量条容易被误认为掌握进度；重复手记与 Journal 分工模糊；巨大的标题和统计占据首屏，计划空卡片和私人入口比可用功能更突出。Works 的方向目录也不能替代项目进展或成果证据。

## 导航与职责

主站页眉为 Index / Journal / Studio。Journal 是按时间阅读的公开手记；Studio 是学习与实践的工作台。Works 归入 Studio 的项目实践，保留 /projects 作为项目目录与后续详情入口，避免旧链接失效。

Studio 推荐内部导航：概览、学习路线、任务与练习、项目实践、学习档案。私人权限以具体数据和操作体现，不占据整个公开首页。桌面使用紧凑栏目导航和主要内容区，手机优先显示当下状态与入口。

| 功能 | 回答的问题 | 最小实用内容 | 公开与私人边界 |
| --- | --- | --- | --- |
| 概览 | 我在哪，接下来做什么 | 已确认当前方向、当前任务/项目、最近有效变化、需要处理的卡点 | 仅选定公开概要；原始卡点和个人反馈受保护 |
| 学习路线 | 哪些已学习，哪些需要练习 | 稳定知识目录、阶段与前置关系、状态、支撑记录 | 可发布目录与确认状态；详细评估依据私人 |
| 任务与练习 | 本次具体做什么，怎样算完成 | 当前任务、目标、验收条件、练习提交、结果和重试 | 批准发布的任务简介可公开；提交/修改/反馈登录 |
| 项目实践 / Works | 学到的知识怎样落地 | 项目状态、里程碑、成果链接、关联知识、验证与复盘 | 已公开成果可看；草稿、未公开代码和调试细节私人 |
| 学习档案 | 结论是否有依据，怎样纠正 | 证据关联、修改历史、阶段复盘、待复习内容与数据管理 | 原始证据/历史/删除和备份受保护；精选复盘可另行发布 |

## 进度必须具有依据

学习记录数量只能叫活动统计，不能叫能力完成率。知识点状态至少区分未确认、学习中、能解释、能独立完成、待复习；具体判定需带证据与时间。AI 辅助的成功产物不等于个人独立能力，缺证据保持未知。整体百分比需要稳定目标范围与明确完成条件后才能计算。

学习路线不是把全部长期课程堆在首页；首页优先呈现当前阶段与下一步。计划执行器未接通时，不展示自动安排、提醒或假任务。已开始任务需要保持稳定，学校紧急事项和明确意愿可调整，临时兴趣不自动推翻路线。

## 项目实践

先归并现有三个项目方向，明确其为蓝图而非已完成成果。后续每个项目需要目的、当前状态、下一里程碑、验收条件、代码/演示与复盘；状态由真实工作与确认更新。项目与学习路线相互关联，避免重复登记同一份成果证据。

## 前端重做顺序

1. 先完成 Works 导航归并，共用项目方向数据源；这是本批实际改动。
2. 重做 Studio 概览：缩小装饰性标题，移除把频次当能力的视觉表达，首屏以当前状态和可用入口为主。减少重复 Journal 内容与空卡片。
3. 接入知识目录、项目状态与任务的真实数据模型，再实现独立栏目；不预先铺满不能使用的模块。
4. 接入练习证据、评估和规划闭环，再提供待复习与阶段变化。真实 owner、备份和接入要求继续保留。

当前已经有公开手记统计、私人记录保存/读取/纠正/历史/删除和本地备份服务。知识路线、任务/练习系统、项目状态、能力评估、自动计划和正式备份操作尚未完成。继续按明确的小批次推进，不把导航或视觉调整算作这些后台功能完成。
