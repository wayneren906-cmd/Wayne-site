# 自动学习记录同步

## 运行方式

由本聊天中的 Codex 定时任务读取「C语言摸底学习」和「每日学习复盘」，整理后调用独立的 `/api/sync/records`。Cloudflare 的定时任务继续保存既有记录的快照；聊天检索和摘要在 Codex 执行。

北京时间每天 06:00 处理刚结束的学习日：前一天 06:00（含）至当天 06:00（不含），归入前一天的日期。先读取网站现有内容，保留人工记录；只有真实学习证据才可更新，计划、讲解示例和建议练习不能记为已完成。无法核实完整范围时，只能明确注明已读取的片段并补充可靠信息，不得声称覆盖所有聊天或删除既有内容。

本机任务需要电脑开机、Codex 应用运行，以及当前聊天的检索和网络权限可用。初次手动同步的成功不等于首个定时运行已验证。

## 凭证和保护

- `data/sync-credential.json`：本机随机令牌，已经被 Git 忽略。不可上传、打印或写进任务提示词。
- `SYNC_TOKEN_SHA256`：Worker Secret，仅保存令牌摘要。未配置时同步 API 拒绝服务；错误凭证返回 401。
- `data/sync-state.json`：上次成功同步的版本。日期已有人工记录但尚未接管，或者人工编辑导致版本变化时，客户端停止同步。
- `data/sync-pending.json`：提交前保存的确切草稿，用于首次创建或接管时网络中断后的安全重试；核对成功后清除。
- 服务端 POST 使用 `expectedRevision` 原子写入；版本冲突返回 409，不自动重新读取后强行覆盖。
- 重复提交相同内容不增加版本；客户端必须再次读取并核对内容、版本和更新时间，才记录本机成功状态。
- 管理员 `/admin` 和 `/api/admin/*` 继续通过 Cloudflare Access 登录。

## 上传已核实的草稿

将 `{date, items:[{label,text}], practice, expectedRevision}` 保存到被忽略的 `data` 目录。在项目目录运行：

```powershell
node scripts/sync-record.mjs data/sync-draft-2026-10-10.json
```

输出只包括日期、版本、是否无变化和核对状态。初次合并已有人工记录，必须保留原内容并人工核对后才能添加 `--adopt-existing`；定时任务不得使用此参数。

更换凭证时同时更新本机令牌与 Worker 的 `SYNC_TOKEN_SHA256` Secret。通过标准输入上传摘要，不能把凭证放进命令参数、GitHub 仓库、日志或聊天。新增秘密后重新运行项目 Wrangler 的 `types` 命令；保持生成类型与配置一致。

每日同步失败、版本冲突或确实缺少来源时报告需要处理的问题。没有新学习证据时保持安静，不编造当天记录。
